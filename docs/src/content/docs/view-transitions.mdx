The [View Transitions API](https://developer.mozilla.org/docs/Web/API/View_Transition_API) lets the browser take a snapshot of the old page and the new one and animate between them. Turn it on with one option:

```js
const pagefold = new Pagefold({ native: true })
```

When the browser supports `document.startViewTransition`, Pagefold performs the content swap inside it. Browsers without it, or visits with `native` off, use the normal flow. Pagefold adds `pagefold-native` to the `html` element when it is active, so your CSS can tell.

## Customizing the transition

The browser animates `::view-transition-*` pseudo-elements. Change them with CSS:

```css
::view-transition-old(root),
::view-transition-new(root) {
  animation-duration: 0.4s;
}

/* Keep a header in place instead of fading it */
header {
  view-transition-name: header;
}
```

Elements with the same `view-transition-name` on the old and the new page morph into each other.

## Transition types

A site usually wants a different animation for going forward than for going back. Give the visit a name and match it in CSS:

```js
pagefold.hooks.on('visit:start', (visit) => {
  if (visit.to.url.startsWith('/work')) visit.animation.types.push('zoom')
})
```

```css
:root:active-view-transition-type(zoom)::view-transition-new(page) {
  animation: zoom-in 0.5s both;
}
```

Pagefold also adds `forwards` or `backwards` on visits made with the back and forward buttons, so the example above needs no JavaScript for them. Set `animateHistoryBrowsing: true`, or those visits are not animated at all.

Types are newer than the rest of the API, so check the [support table](https://developer.mozilla.org/docs/Web/API/ViewTransition/types). In a browser that has View Transitions but not types, the transition still runs, without the names, so write the CSS so that the default animation looks right on its own.

## Reaching the transition

While the swap runs inside a transition, `visit.transition` is the browser's `ViewTransition`. Use it for anything the CSS cannot do, such as animating the snapshots with the Web Animations API:

```js
pagefold.hooks.on('page:view', (visit) => {
  visit.transition?.ready.then(() => {
    document.documentElement.animate(
      { clipPath: ['circle(0 at 50% 50%)', 'circle(150% at 50% 50%)'] },
      { duration: 600, pseudoElement: '::view-transition-new(root)' }
    )
  })
})
```

Do not `await visit.transition.ready` inside a hook that runs during the swap (`content:*`, `page:view`). The swap waits for your hook and `ready` waits for the swap, so the visit would never finish. Use `.then`, as above.

It is `undefined` when `native` is off, when the browser has no View Transitions, or before the swap starts, so use `?.`.

## Using only the browser's animation

Pagefold still runs its own phases around the native transition: the state classes are added and, by default, it waits for CSS transitions on `transition-` elements. If you want the native transition to be the only animation, turn that off:

```js
new Pagefold({ native: true, animationSelector: false })
```

## Reduced motion

```css
@media (prefers-reduced-motion: reduce) {
  ::view-transition-group(*),
  ::view-transition-old(*),
  ::view-transition-new(*) {
    animation: none !important;
  }
}
```

The [A11y plugin](/docs/a11y/) can also turn animation off for those visits.

## Tested

The browser tests check that the option calls the API once per visit, that `visit.transition` reaches the hooks, and that the types, including `forwards` and `backwards`, arrive in the transition. The look of the transition depends on your CSS.
