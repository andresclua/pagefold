Import it from `pagefold/scroll` (about 1.3 KB minified and compressed, shared code included).

```js
import PagefoldScroll from 'pagefold/scroll'

new Pagefold({
  plugins: [
    new PagefoldScroll({
      duration: 800,
      offset: () => document.querySelector('header').offsetHeight,
      animateScroll: { betweenPages: false }, // jump between pages, glide to anchors
    }),
  ],
})
```

## What it animates

| Kind | Example |
|---|---|
| `betweenPages` | Going to another page: scrolls to the top, or to the anchor if the URL has one |
| `samePageWithHash` | A link to `#section` on the same page |
| `samePage` | A link to the page you are already on, which scrolls to the top |

## Reset or restore

On every visit the page goes back to the top, as a browser would. On back and forward visits it goes to **where you were** when you left that page. Pagefold remembers the position of each page you leave, so this also works when `animateHistoryBrowsing` is on, which makes Pagefold, and not the browser, responsible for scrolling.

`shouldResetScrollPosition` changes this for links. A custom "back" link would normally scroll the new page to the top, while visitors expect it to behave like the back button:

```js
new PagefoldScroll({
  shouldResetScrollPosition: (link) => !link.matches('.backlink'),
})
```

## Scroll containers

An element with its own scrollbar, such as an overflowing table or a sidebar, is not part of the window's scroll. Mark the ones that matter and Pagefold resets them on a visit and restores them on back:

```html
<aside data-pagefold-scroll-container>...</aside>
```

Or choose them with the option: `scrollContainers: '.sidebar, .results'`. They are remembered by their order in the page, so a container that is replaced by a visit starts at the top anyway, and one that stays outside the containers is the one that benefits.

## Marking the target

`:target` stops working on sites that add their own history entries. With `markScrollTarget: true` the element a hash points to gets the attribute `data-pagefold-scroll-target`, which you can style instead:

```css
[data-pagefold-scroll-target] {
  outline: 2px solid var(--accent);
}
```

## Hooks and the instance

`scroll:start` and `scroll:end` fire around an animated scroll. The plugin also adds `pagefold.scrollTo(position, animate)`, the same as calling it on the plugin.

```js
pagefold.hooks.on('scroll:start', () => document.body.classList.add('is-scrolling'))
pagefold.hooks.on('scroll:end', () => document.body.classList.remove('is-scrolling'))
await pagefold.scrollTo(2000, true)
```

## Stopping

The animation stops as soon as the user takes over (wheel, touch, key press or mouse down) or a new visit starts.

## From code

```js
const scroll = new PagefoldScroll()
await scroll.scrollTo(0)                   // animated
await scroll.scrollTo(document.querySelector('#pricing'))
await scroll.scrollTo(300, false)          // jump
```

It replaces the default behavior of the `scroll:top` and `scroll:anchor` hooks. Without `animateHistoryBrowsing`, back and forward visits keep the browser's own scroll restoration.

## Common problems

- **The page jumps instead of gliding.** Between pages the old content is usually hidden while it changes, so many sites turn `betweenPages` off. Check `animateScroll`.
- **A sticky header covers the target.** Set `offset` to the header's height, as in the example above.
- **Back and forward do not animate.** They keep the browser's own scroll restoration, on purpose.
