Import it from `pagefold/fragment` (about 1.2 KB minified and compressed, shared code included).

```js
import PagefoldFragment from 'pagefold/fragment'

new Pagefold({
  containers: ['#list', '#detail'],
  plugins: [
    new PagefoldFragment({
      rules: [
        { from: '/users', to: '/users/:id', containers: ['#detail'], name: 'detail' },
        { from: '/users/:id', to: '/users', containers: ['#detail'] },
      ],
    }),
  ],
})
```

Going from `/users` to `/users/7` replaces only `#detail`. The list, with its scroll position and its state, is not touched. Because rules match on the page you leave **and** the page you enter, the way back needs a rule of its own, as in the second entry.

Here is what the visit does to the page, with `#list` and `#detail` as containers:

<Panes
  columns="1fr 2fr"
  before={{ url: '/users', panes: [{ name: '#list', text: 'scrolled, filtered' }, { name: '#detail', text: 'nothing selected' }] }}
  after={{ url: '/users/7', panes: [{ name: '#list', text: 'scrolled, filtered', state: 'kept' }, { name: '#detail', text: 'user 7', state: 'replaced' }] }}
  caption="Only #detail changes. The list keeps its scroll position, its filter and anything playing in it."
/>

Try it. Scroll the list or type in the field, then click a name: only the right side changes.

## A rule

| Field | What it does |
|---|---|
| `from`, `to` | Path patterns, or a list of them. `:name` and `*` work as in [JS](/docs/js#matching). |
| `containers` | The only containers replaced by matching visits |
| `name` | Becomes the animation name, as `data-pagefold-animation` would |
| `scroll` | Scroll after the visit. `true` goes to the top, a selector goes to that element, and a function `(visit) => boolean \| string` decides for each visit. Fragment visits keep the scroll position by default |
| `focus` | With the [A11y plugin](/docs/a11y): a selector to focus after these visits, or `false` to leave focus alone |
| `if` | `(visit) => boolean`. Return `false` to skip the rule for that visit, even when the paths match |

## Animations

The animation classes go on the fragment containers, not on the `html` element, so the rest of the page is not animated. Style it like any other visit:

```css
#detail.is-animating {
  opacity: 0;
}
```

## When it falls back

A rule is only used if **every container in the rule is on the current page**. And if the **new** page does not contain one of them, the rule is dropped for that visit and Pagefold replaces the normal containers instead, so you never end up with a half-updated page.

That works when a normal container is bigger than the fragment. Here `#pagefold` is the normal container and `#detail` is inside it:

<Panes
  columns="1fr"
  before={{ url: '/projects/a', panes: [{ name: '#pagefold', text: 'contains #detail and the rest of the page' }] }}
  after={{ url: '/projects', panes: [{ name: '#pagefold', text: 'no #detail on this page: everything inside is replaced', state: 'replaced' }] }}
  caption="The rule asked for #detail only, but the new page has none, so the whole #pagefold is replaced."
/>

If the new page is also missing one of the **normal** containers, there is nothing safe to replace. The visit fails and the browser loads the page normally, as for any visit that cannot be done.

`visit.fragment` tells you whether a visit is a fragment visit.

## Common problems

- **The way back replaces everything.** A rule needs the page you leave **and** the page you enter. Add a second rule for the return trip.
- **A rule never applies.** Every container in the rule must exist on the current page, and both patterns must match. Turn on the [Debug plugin](/docs/debug) to see what the visit does.
- **The scroll position resets.** Fragment visits keep it unless the rule has `scroll: true`.
